# 탐지 정확성 보완 및 폐쇄망 설치 검증

## 수정 범위

- Python/JavaScript 함수 진입·종료와 중첩 함수에서 변수 상태를 분리하여 다른 스코프의 값을 잘못 `confirmed`로 승격하는 문제 보완.
- 같은 함수의 위험 흐름은 유지하고, JavaScript 제어 블록을 함수 경계로 오인하지 않도록 수정.
- 코드·비밀값 탐지의 숨겨진 규칙별 5건 제한 제거. 최종 응답의 200건 제한은 유지하며 잘림을 명시.
- 라이브러리 파일명만으로 코드를 제외하던 분기 제거.
- 파일 전체에 인증·속도 제한 관련 문자열이 있다는 이유만으로 모든 후보를 숨기던 억제 제거. 적용 범위를 입증하지 못한 경우 검토 후보로 유지.
- Compose/Kubernetes 주석을 따옴표와 구분하고, 여러 줄 문자열 안의 설정 예시는 구조로 오인하지 않도록 보완. 일반 파일명에서도 Kubernetes 메타데이터를 확인.
- `unevaluated_files`에 검사하지 않은 파일, 범위, 이유를 반환. 의존성 CVE·함수 간 흐름·선택 기준 필터를 coverage gap으로 안내.
- `reason`에 구체적인 로컬 판정 근거를 보존하고 인라인 비밀값 대입도 마스킹.
- 폐쇄망 반입 문서에 고유 이미지 태그, 압축·해시 검증, 설정 생성, 이미지 적재, 기동과 운영 확인 절차를 정리.

## 의도적으로 남겨둔 한계

- 2,000바이트가 넘는 줄이 있는 파일은 자원 소진 방지를 위해 **파일 전체를 미검사**로 반환한다. 원본을 안전하게 나누거나 생성 전 소스를 제공해야 한다.
- Svelte 등 미지원 코드 형식은 언어 지원을 새로 구현하지 않았고, 코드 검사 미실행을 명시한다.
- CVE DB 대조, 프로젝트 전체 호출 관계, 실행 환경과 실제 LLM의 누락·왜곡 여부는 별도 검증 대상이다.
- 함수·설정 분석은 여전히 보수적인 휴리스틱이며, 전 언어 AST·YAML 파서 또는 경로 민감 분석으로 대체한 것은 아니다.
- 고정 셸 호출 등은 검토 후보로 남을 수 있다. `confirmed`도 실제 악용 가능성이나 정식 기준 위반의 최종 판정이 아니다.

원래의 결함 재현 기록은 `detection-audit-2026-09-09.md`와 기존 JSONL에 보존한다. 수정 후 결과는 `detection-audit-after-2026-09-09.jsonl`로 분리한다.

## 최종 검증 결과

- 로컬 전체 테스트: **78개 통과**.
- Linux amd64 Docker 이미지 내부 전체 테스트: **78개 통과**. 네트워크 차단, read-only 파일시스템, 임시 tmpfs 조건.
- 실제 HTTP MCP 호출: 임시 토큰 인증 성공, 반복 후보 6건 모두 반환, 임시 소스 삭제 확인. 운영 토큰은 사용하지 않았다.
- 반입 번들 생성 및 검증: 전체 파일 SHA256, SBOM 존재, 이미지 amd64·비관리자 UID, Compose 구성, 내부 네트워크의 외부 TCP/DNS 차단 확인.
- Python compileall, 의존성 일관성 검사, 셸 스크립트 구문 및 diff 공백 검사 통과.
- 설치 문서의 셸 블록 10개 구문 검사 통과. 실제 서버 CA/TLS·운영 LLM 연결은 별도 확인 필요.
